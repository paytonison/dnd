# Full SRD 5.2.1 lifecycle: implementation handoff

Prepared September 8, 2026 against the current `srd55` module and `srd55-core` version **1.0.0**. This document is an implementation checklist for the next part of the repository plan. It does not mark the expansion implemented or change the validated first release.

The target is all **12 classes and the 12 subclasses actually contained in SRD 5.2.1**, levels **1–20**, with their creation choices, advancement, multiclassing, relevant equipment, spells, and character-sheet effects. Classes or subclasses found only in other publications need their own licensed source packs and coverage records. Do not silently import 2014 or other 2024 book rules to fill an SRD gap.

Primary reference: [official SRD resource page](https://www.dndbeyond.com/srd) and its [English SRD 5.2.1 PDF](https://media.dndbeyond.com/compendium-images/srd/5.2/SRD_CC_v5.2.1.pdf). The PDF has 364 pages; the printed and one-based PDF page numbers match. The source was inspected on September 8, 2026, including rendered progression tables on pages 24, 26, 28, 31, 36, 41, 47, 50, 53, 58, 62, 65, 71, and 77. Source ranges below refer to this publication, not the Player's Handbook. Retain the attribution in `data/packs/srd55-core/ATTRIBUTION.md` and record changes in the new pack's license metadata.

## 1. Preserve the existing baseline

The current implementation has 292 content entries and an experimental Fighter/Wizard level 1–3 slice. Its 11 SRD test cases passed 260 assertions when this handoff was prepared. `docs/sources-srd55.md` records its independent numerical examples and scope limits.

- [ ] Keep `tests/test_srd55.cpp` as the first-slice regression suite. Preserve the original expected results: Dwarf Fighter maximum HP **13/22/31**, chain-mail-and-Defense AC **17**, greatsword attack **+5**; Dwarf Wizard HP **9/16/23**, unarmored AC **11**, spell DC **13**, spell attack **+5**, and level-3 slots **4/2**.
- [ ] Preserve original `choices`, accepted `rolls`, advancement history, module version, and pack pins when loading. Add migration tests using actual version-1 saved JSON, including objects or arrays at numeric JSON-pointer paths such as `/hp/2` and `/spellbook/1`.
- [ ] Expand in a new module/pack version. The current `findEdition(id)`/single-version registry cannot simultaneously resolve two versions of the same edition: add exact `(id, version)` resolution or an explicit, tested compatible-version dispatcher. Keep the old pack available. An upgrade must produce a reviewable migrated copy; it must not rewrite an old save or silently substitute the new rules.
- [ ] Run the entire B/X, common persistence/content, and Qt suites after every shared-contract change. A higher SRD feature count does not excuse a B/X regression.
- [ ] Keep coverage experimental until the gates in section 8 pass. Track each feature as cataloged, implemented, or independently verified; a source record or descriptive paragraph alone is not implementation of a missing prerequisite, choice, resource maximum, or calculation.

## 2. Public-contract changes and existing code that must change

These are engineering proposals based on the live code, not additional published game rules. The reusable contracts should continue to support edition-specific mechanics without adding universal 5e-only fields to `CharacterDocument`.

Use small C++ evaluators for new mechanics and declarative data for ordinary additions that use those mechanics. Merely removing the ID allowlist or changing `3` to `20` would leave incorrect subclass, HP, feat, resource, spell, and multiclass behavior.

## 3. Shared SRD lifecycle and progression checklist

The authoritative progression and multiclass rules are on [pages 23–26](https://media.dndbeyond.com/compendium-images/srd/5.2/SRD_CC_v5.2.1.pdf#page=23).

- [ ] Transcribe and visually verify all 20 character XP thresholds and the proficiency steps: **+2 at 1**, **+3 at 5**, **+4 at 9**, **+5 at 13**, **+6 at 17**. Level 20 starts at **355,000 XP**. Keep milestone advancement separate from an explicitly supplied XP total.
- [ ] First character level uses the initial class's maximum Hit Die plus Constitution. Every later character level uses the newly chosen class's fixed/accepted die result plus Constitution, minimum **1**. Group remaining Hit Dice by die size rather than printing one `NdX` string for all characters.
- [ ] Apply Constitution modifier changes retroactively to all attained levels. Apply class/species HP bonuses using their specified class or character-level scope. Preserve the HP dice already accepted before an ability increase.
- [ ] Encode multiclass primary-ability prerequisites against the new class **and current classes**: Fighter uses Strength **or** Dexterity; Monk Dexterity **and** Wisdom; Paladin Strength **and** Charisma; Ranger Dexterity **and** Wisdom; other classes use the primary ability shown in their core traits. Check values at the relevant advancement event.
- [ ] Entering another class grants only its “As a Multiclass Character” package. Do not grant another starting equipment kit, another initial saving-throw pair, or another maximum first-level Hit Die.
- [ ] Extra Attack features do not add together. Fighter's explicit third/fourth attacks and Warlock's applicable invocation chain need named nonstacking rules and weapon scope. Multiple AC bases likewise remain alternatives.
- [ ] Compute combined Spellcasting slots only when the multiclass Spellcasting rules apply: full levels of Bard/Cleric/Druid/Sorcerer/Wizard and half levels of Paladin/Ranger, **rounded up** as specified. Preserve per-class preparation eligibility. Keep an explicit regression for odd half-caster levels, and verify the interpretation when both Paladin and Ranger contribute odd levels rather than importing the 2014 rounding rule.
- [ ] Keep Pact Magic slots outside that combined progression; allow the published cross-use with prepared spells from Spellcasting classes. Mystic Arcanum uses are separate free castings, not additional general-purpose high-level Pact slots.
- [ ] Add a campaign setting for the published higher-level starting-equipment guide. Its GP and item allowances are GM-controlled guidance, not mandatory automatic gifts: levels **2–4** normal equipment + one Common item; **5–10** add `500 + accepted d10 × 25 GP`, one Common and one Uncommon; **11–16** add `5,000 + accepted d10 × 250 GP`, two Common/three Uncommon/one Rare; **17–20** add `20,000 + accepted d10 × 250 GP`, two Common/four Uncommon/three Rare/one Very Rare. Accepted money rolls are saved. [Page 24](https://media.dndbeyond.com/compendium-images/srd/5.2/SRD_CC_v5.2.1.pdf#page=24)
- [ ] Expose the published optional bonus feat every **30,000 XP above 355,000** at level 20 as a campaign option. It grants an eligible feat without creating class level 21. Preserve campaign settings when Advanced mode is hidden. [Page 24](https://media.dndbeyond.com/compendium-images/srd/5.2/SRD_CC_v5.2.1.pdf#page=24)

## 5. Species, feats, spells, and equipment

### Species and feat grants

- [ ] Extend the existing species data to every character-level threshold in [pages 84–86](https://media.dndbeyond.com/compendium-images/srd/5.2/SRD_CC_v5.2.1.pdf#page=84): Dragonborn breath damage at **5/11/17**, flight at **5**; Goliath Large Form at **5**; Elf/Tiefling level-**5** lineage spells. Replace hardcoded two-use origin notes with proficiency-based capacities wherever the source uses proficiency. Keep species casting ability and independent free castings.
- [ ] Model persistent Human Origin-feat grant separately from background grants and every later feat grant. Continue to allow repeatable Skilled with independent proficiency choices; Magic Initiate repetitions must use different spell lists. Preserve replacement history for Magic Initiate and High Elf cantrip choices rather than claiming all changes are freely available at any time.
- [ ] Add General feats **Ability Score Improvement** and **Grappler**; implement level/ability prerequisites, score choices, repeatability, maximum **20**, and all sheet-affecting effects. A level-4 grant is not a free edit of the base ability score. Fighter and Rogue's extra ASI opportunities need their own class-level events. [Page 87](https://media.dndbeyond.com/compendium-images/srd/5.2/SRD_CC_v5.2.1.pdf#page=87)
- [ ] Add the seven SRD Epic Boons: **Combat Prowess, Dimensional Travel, Fate, Irresistible Offense, Spell Recall, the Night Spirit, Truesight**. Encode level **19+**, Spell Recall's Spellcasting prerequisite, each feat's eligible score choices, maximum **30**, and per-feature activation/recharge conditions. Do not grant unrestricted +1 to any ability for a boon whose source narrows the choices. [Page 88](https://media.dndbeyond.com/compendium-images/srd/5.2/SRD_CC_v5.2.1.pdf#page=88)
- [ ] Retain the four supported SRD Fighting Styles, and permit the class features that grant them to select them at the right levels. Do not add non-SRD styles merely because they exist in another rules source.
- [ ] Document the published custom-background procedure as a campaign option and structured-pack template, using the existing import workflow; in-app content authoring remains outside the original release scope. A custom background definition needs three eligible abilities, one Origin feat, two skills, one tool, and a **50 GP** equipment package including unspent coin, excluding Martial weapons and armor. Preserve source/publisher/origin metadata; do not label it an additional official named background. [Pages 192–193](https://media.dndbeyond.com/compendium-images/srd/5.2/SRD_CC_v5.2.1.pdf#page=192)

## 6. Implementation order with reviewable exits

1. **Versioned advancement and source schemas.** Add ordered class-level records, legacy adapter, exact module-version dispatch, typed feature grants/prerequisites/resources, and extended validators. Keep existing Fighter/Wizard behavior and B/X tests green. Exit with synthetic mixed-Hit-Die/feature-dependency fixtures and one real saved version-1 character upgraded into a separate copy.

Exit with every level 1–20 for both classes, published slot boundaries, preserved first-slice fixtures, and a printed level-20 sheet with no clipped spells or omitted feature/source annotations.
3. **Add Barbarian, Rogue, and Monk.** Exercise alternative AC, nonstacking attack counts, repeated expertise, martial damage scaling, restricted equipment, action/point resources, and conditional features. Exit with all single-class levels and their complete SRD subclasses; keep formula selection explainable.
4. **Add Cleric, Druid, Bard, Sorcerer.** Implement per-class preparation and replacement policies, granted spells, order choices, transformation/companion sheets, sorcery-point conversion, and Metamagic. Exit with all class-level and selection boundaries plus class/source spell-profile tests.
5. **Add Paladin, Ranger, Warlock and full multiclass acceptance.** Complete half-caster and Pact resource handling, invocation dependencies, class-entry training, and cross-pool spell use. Exit with all 12 single classes through 20 and the mixed-class fixtures below. Do not defer prerequisite or class-entry logic until after presenting multiclass choices as available.
6. **Complete equipment/current-state integration and release verification.** Finish the SRD item coverage ledger, rest/resource commands, active effects, higher-level start presets, printable spell/form/item sections, migration/recovery checks, and Mac GUI acceptance. Run cross-platform CI and clearly report which OS workflows were actually executed. Only then update coverage from experimental to implemented/verified at the appropriate feature level.

These slices can run in parallel only after their shared schema is agreed. Assign class families to separate files/data files and keep the shared progression, resource, and spellcasting evaluators under one owner to avoid twelve slightly different implementations of the same rule.
